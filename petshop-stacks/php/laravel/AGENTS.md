## Commands

```bash
# Install
composer install

# Run tests (no database needed)
php artisan test
# or
vendor/bin/phpunit --testsuite=Unit

# Run server (port 8080)
php artisan serve --port=8080

# Mutation testing
./vendor/bin/infection --threads=4
# or
composer mutate
```

### Docker (when PHP is not installed locally)

```bash

docker run --rm -v "$(pwd):/app" -w /app php:8.4-cli \
```

## API Base Path

Routes are registered under `/api/v3` (set via `apiPrefix` in `bootstrap/app.php`).

Example: `POST /api/v3/pet`, `GET /api/v3/store/inventory`, `GET /api/v3/user/login`

## Persistence Conventions

These follow the repo-wide schema invariants exactly:

- `category`, `photo_urls`, `tags` are JSON columns; `category` stored as JSON string
- `pet.status` / `order.status` are PostgreSQL enum types (`pet_status`, `order_status`); cast with `::pet_status` / `::order_status` on write; read with `status::text`
- IDs: `nextval('<table>_id_seq')` when omitted in request (sequences: `pet_id_seq`, `order_id_seq`, `user_id_seq`, `pet_photo_id_seq`)
- Writes: `INSERT ... ON CONFLICT (id) DO UPDATE` upserts
- Tables: `pet`, `"order"` (quoted), `"user"` (quoted), `pet_photo` (BYTEA)
- `uploadFile`: verifies pet exists, inserts raw request body into `pet_photo.content` (BYTEA keyed by `pet_id`), returns ApiResponse with byte count
- `logoutUser`: stateless no-op, returns 200

## Test Strategy

Unit tests in `tests/Unit/` test `InMemoryPetstoreRepository` directly — **no database needed**.

- `PetRepositoryTest.php` — 23 assertions covering all pet operations
- `StoreRepositoryTest.php` — covers order CRUD + inventory
- `UserRepositoryTest.php` — covers all user operations + login/logout

Integration tests (hitting PostgreSQL) are **not** included; the shared DB-free pattern keeps CI fast.

## Mutation Testing

Config: `infection.json5`  
Target: `app/Repositories/InMemoryPetstoreRepository.php`  
Excluded: `PostgresPetstoreRepository.php` (requires live DB)

```bash
./vendor/bin/infection --threads=4
```

Results written to `infection.log`.

## Generator Note

The `openapi-generator-cli` `php-laravel` generator (v7.23.0) was run during setup and produced:
- API interfaces (`Api/PetApiInterface.php` etc.) — used as design reference only, not included
- Model classes — used as design reference only, not included
- Stub routes (`routes.php`) — content replicated in `routes/api.php`

The generator does NOT produce a runnable Laravel application, so the project was created with `composer create-project laravel/laravel` and the implementation was hand-written following the generated stub interfaces.
