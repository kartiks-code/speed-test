# Rust Server — Agent Guide

This directory contains the Rust petstore server generated by OpenAPI Generator 7.23.0 and extended with real PostgreSQL persistence.

## Working Directory

Run all commands from `rust/` unless stated otherwise. The server listens on `127.0.0.1:8080`.

## Database Setup

The `rust-server` PostgreSQL database lives in the shared Docker Compose stack defined in `../database/`.

```bash
cd ../database
docker compose up -d
./create-databases.sh          # creates rust-server (idempotent)
./apply-schemas.sh             # applies postgresql_schema.sql + postgresql_schema_oauth2.sql
cd ../rust
```

### Environment variables

Copy `.env.example` to `.env` and adjust if needed (the defaults match `database/.env`):

| Variable | Default | Description |
|---|---|---|
| `DATABASE_URL` | — | Full DSN; overrides all variables below |
| `POSTGRES_HOST` / `PGHOST` | `localhost` | Postgres host |
| `POSTGRES_PORT` / `PGPORT` | `5434` | Host port (matches `database/.env`) |
| `POSTGRES_USER` / `PGUSER` | `myuser` | Postgres user |
| `POSTGRES_PASSWORD` / `PGPASSWORD` | `mypassword` | Postgres password |
| `POSTGRES_DB` / `PGDATABASE` | `rust-server` | Database name |

The server loads `rust/.env` at startup (non-fatal if absent) via `dotenvy`.

## Running the Server

```bash
# Optional: enable request logging
RUST_LOG=info cargo run --example petstore-server-server
```

The server starts on `http://127.0.0.1:8080`. All routes are under `/api/v3`.

## Code Layout

| Path | Purpose |
|---|---|
| `src/` | **Generated — do not edit.** Models, HTTP router, API trait definitions. |
| `src/lib.rs` | `Api<C>` trait + all `*Response` enums. |
| `src/models.rs` | Generated Petstore DTOs (`Pet`, `Order`, `User`, etc.). |
| `src/server/mod.rs` | Generated HTTP dispatch layer (hyper + regex routing). |
| `examples/server/main.rs` | Binary entry point; builds the pool and starts the server. |
| `examples/server/server.rs` | **Implemented `Api` trait** — all 19 CRUD operations with sqlx. |
| `examples/server/db.rs` | Pool factory (`create_pool()`) and DSN resolution from env. |
| `examples/server/server_auth.rs` | JWT bearer auth helpers (generated). |

## Implementation Conventions

- **Driver**: `sqlx` 0.8 with `runtime-tokio` + `postgres` + `chrono` features. Runtime queries only (no compile-time `query!` macro); no ORM.
- **JSON columns**: `photo_urls` and `tags` are stored as JSON. Written via `serde_json::to_string(...)` + `$n::json` cast in SQL; read back as `String` then deserialized.
- **category column**: Stored as TEXT containing a JSON string (same as siblings).
- **Enum columns**: `pet.status` (`pet_status`) and `order.status` (`order_status`) are Postgres enum types. Cast in SQL with `$n::pet_status` / `$n::order_status`; read back as `status::text`. Converted to/from model enums using their `Display` / `FromStr` impls.
- **Timestamps**: `order.ship_date` is a `TIMESTAMP` (no timezone) column. Converted to/from `chrono::NaiveDateTime` (UTC assumed both directions).
- **ID generation**: When a request omits an id, the server uses `COALESCE(MAX(id), 0) + 1` from the relevant table.
- **Upserts**: `add_pet`, `place_order`, `create_user`, `create_users_with_list_input` use `INSERT … ON CONFLICT … DO UPDATE`.
- **upload_file**: Verifies the pet exists; does not persist binary data. Returns a mock `ApiResponse`.
- **logout_user**: Stateless no-op; always returns success.
- **Tables used**: `pet`, `"order"`, `"user"`. Standalone `category` and `tag` tables from the schema are not queried.

## Verification

```bash
# Build check
cargo build --example petstore-server-server

# Run server
RUST_LOG=info cargo run --example petstore-server-server &

# Add a pet
curl -s -X POST http://127.0.0.1:8080/api/v3/pet \
  -H 'Content-Type: application/json' \
  -d '{"name":"Fido","photoUrls":["http://example.com/fido.jpg"],"status":"available"}' | jq .

# Get inventory
curl -s http://127.0.0.1:8080/api/v3/store/inventory | jq .

# Create a user
curl -s -X POST http://127.0.0.1:8080/api/v3/user \
  -H 'Content-Type: application/json' \
  -d '{"username":"alice","password":"secret","email":"alice@example.com"}' | jq .
```
